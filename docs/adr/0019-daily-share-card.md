# 0019 每日报告分享卡（v2.4）

日期：2026-10-31。状态：已实现，模拟器验收（待真机）。前作见 [ADR 0018](0018-quiz-resume-and-larger-group.md)。

## 背景

用户提出「做每日学习报告分享按钮，导出为图片」。开工前讨论定下三件事：

1. **卡片内容 = 数字 + 13 周热力图**（不是长文案，也不是趋势图）；
2. **入口 = 今日页标题旁的图标 + 先看预览**；
3. **视觉选推荐方案**：左对齐的书页版式（纸色底、大号衬线数字「连续 N 天」、
   细分隔线、两栏今日数字、13 周热力图、页脚副标题），不是居中海报，也不是
   热力图占满整页的版本。用户同时要求「开工之前先 push 上一个版本」——v2.3.0 已发布。

## 决定

1. **卡片是固定像素版面，与设备无关**。`feature/home/ShareCard.kt` 里版面按
   `1080×1440`（3:4）排版：`CompositionLocalProvider(LocalDensity provides Density(1f, 1f))`
   里 `requiredSize(1080.dp, 1440.dp)`，所有字号直接写 `sp`。这样同一份代码在任何
   屏幕密度与字体缩放下都出同一张图，不随系统字号变化。
2. **用 `GraphicsLayer` 录一次，导出与预览是同一张位图**。卡片在 dialog 里离屏画一次
   （`Modifier.offset` 移出 dialog 窗口），`drawWithContent { layer.record { drawContent() } }`
   录制，等两帧后 `layer.toImageBitmap()`；预览就是这张位图 `Image(FillWidth)`，
   不再另画一份缩放版。曾经试过「1080 版面 + `graphicsLayer` 缩放当预览」，
   在对话框里大子节点会被居中放置、又被裁剪，头部与页脚被切掉——预览必须是导出结果本身。
3. **只在本机生成 PNG，经 `FileProvider` 交给系统分享**。写 `cacheDir/share/share-card.png`
   （固定文件名、不累积），`FileProvider` 授权 `${applicationId}.fileprovider`，
   `ACTION_SEND` + `image/png`。不加存储权限、不申请相册写入、不上传服务器。
4. **卡片底色固定纸色，不跟深色主题**。它是一张要发出去的海报，深色下反而丢对比；
   预览对话框本身仍跟随主题。
5. **数字口径与今日页一致**。连续天数取 `HomeState.streak`；「今日新学 / 今日回忆」
   由 `DailyLoopService.todayTally()` 用 `learnedWordIdsSince` / `recalledWordIdsSince`
   按**不重复词数**现读，与热力图、趋势同一口径。同一个词今天既学过又回忆过会同时
   出现在两边——两行回答的是两种动作，不是加法。热力图下方的「共 N 天有记录」也是
   不重复词数为正的天数，不用「今天没断」这类可能失真的说法。
6. **版面节奏要在 1440 内留出页脚**。第一版内容溢出，[Column] 把页脚量到 0 高、
   直接看不见——热力图之后还差 34+页脚+72 底边距。最终把顶部留白、段落间距、
   大字号（276→248sp）与热力格（52→48dp）一起收紧，中间留一段 `weight(1f)`，
   页脚固定落在底边距上方；`GraphicsLayer` 只录 1440 高，溢出部分一律丢失。

## 后果

- 导出图恒为 1080×1440 PNG（实测约 64KB），包含品牌名、日期、连续打卡、两项今日数字、
  13 周热力图与页脚；系统分享面板实测能拉起（模拟器）。
- 预览是「打开对话框那一刻」的数据快照，对话框打开期间不会自动刷新；卡片读的就是
  今日页当前显示的那份 `HomeState`，所以图上的数字与屏幕上永远一致。若要实时刷新，
  得等数据变化后重新录制。
- 没配 API key、断网都不影响：整张图只读本地 `review_logs` 与 `daily_loop`。
- 卡片视觉与 `scratch/share-card/b.html` 对应（该目录已 gitignore，只作设计参照）。
