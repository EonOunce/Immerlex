# 0011 易错词与双向易混关联

日期：2026-10-29（第 7 条为 2026-10-30 补充的易混词管理页）

## 背景

用户在阅读页看词卡时需要能：

- 手动把一个词标为易错词，释义自动补全（词库优先，其次离线 ECDICT）；
- 系统**推荐**易混词（常见混淆对 + 拼写邻居），但只推荐，点选后才建立关系；
- 自己填一个英文单词加进易混栏，填好后自动匹配释义；
- 关系双向：点 affect 看到 effect，点 effect 也看到 affect。

易混列表后续还要喂给测验的干扰项（详见测验 ADR）。

## 决定

1. Room v6 新增两张表：`tricky_words`（`word` 主键，`gloss` / `ipa` / `createdAtSec`）与
   `tricky_links`（复合主键 `wordA` + `wordB`，索引 `wordB`）。不建外键：阅读页的词可能
   不在词库里，易错词必须能独立存在。
2. 双向关系只存**一行有序对**（`wordA <= wordB`），查询时两个方向都看。两侧词在建立
   关系时都会 ensure 进 `tricky_words`，所以从任意一侧打开词卡都能看到对方；取消标记
   会同时删掉该词的所有关系。
3. 推荐是纯函数 `core.tricky.ConfusableSuggestions.suggestionsOf`：先给人工整理的常见
   混淆对，再按编辑距离补拼写邻居。阈值：3 字母内只收等长替换邻居（避免 cat → coat
   这类插入噪声）；4 字母内最多 1 个编辑；更长最多 2 个。**绝不自动建立关系**，UI 上
   是可点的 chip。
4. 手动输入走 `TrickyRepository.addManual`：英文归一化为小写，释义先用词库
   `translation`，没有则查 ECDICT，再没有也可以先加入（`gloss` 空着，UI 提示没查到）。
   当前词自己也允许先不在词库中。
5. UI 在阅读页词卡底部（`TrickySection`）：标记/取消标记、易混列表、推荐 chip、手动
   输入。链接里的词点开就是一张独立词卡；不在词库的词只读、不排复习。
6. 迁移 `MIGRATION_5_6` 只建新表，旧数据不动；`TrickyMigrationTest` 锁住 v5→v6 与
   v1→v6 链。
7. **管理页（词库页标题行「易混词管理」）不新增表**：组是 `tricky_links` 上的连通分量，
   由纯函数 `core.tricky.TrickyGroups.components` 现算，所以落单的易错词也自成一组，
   `a-b`、`b-c` 会自然并成一组，不存在"组"这个实体。批量新增解析同一函数
   （`TrickyGroups.parse`：一行一组，组内半/全角逗号分隔，去重后不足两词的行丢掉），
   一组词按 `pairsOf` 两两挂上；往组里加词则与组内每个成员都挂。只有两个写动作：
   **移出**删掉该词在本组内的连线（易错标记留着），**删除**只给落单的词，连标记一起删。
   关系的并合与拆分因此永远由同一套规则给出，UI 不自己拆列表。

## 后果

- 易错标记是**按词**而不是按章：同一词在任何章节的词卡里都显示已标记。
- 推荐宁可少给也不给噪声；常见混淆对的覆盖面靠 `CONFUSABLE_PAIRS` 维护。
- 手动加入的词若不在词库，可读、可作易混，但不会进入 FSRS 调度；想复习需要另行加入
  词库。
- 取消标记会删掉该词两侧的所有易混关系，这是有意的：关系依附于"这个词是易错词"。
- 测验（独立会话）将复用同一份易错词与关系作为干扰项候选。
- 组由关系现算，所以往一组里加一个已经在别组里的词会把两组并成一组；移出一个词也可能
  让剩下的词仍经别条线连在一起。这不是 bug，UI 不承诺"一次改动只影响一组"。
