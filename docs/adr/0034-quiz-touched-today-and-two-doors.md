# 0034 测过一轮就减今日到期：今日页两扇门与结果页的主角（v4.1）

## 背景

用户 2026-11-11 真机用了一阵之后，一句话把 v3.7 那道闸门的副作用点了出来：

> 「我发现现在每天的单词压力太大了，可不可以把今日测验这类测验类型的，只要测过 1 次，就能减少今日到期的词数，
> 但是要进入算法，还是要连续 3 次练习或者在阅读页点过。所以如果你今天只点过一次测验，第二天这个词还是算新词，
> 又会进入今日到期。然后把今日测验（首测）、易错练习、今日复习（第二次及以后测）分成三个入口，今日测验完成后，
> 也有窗口问是否要复习这些词……还有我发现练习完后的界面太简陋了，首先不符合我们重构的 ui 整体风格，
> 还没有起到激励、展示的作用。以上所有和我讨论」

问题的根子在 v3.7：四选一答对只写一条 `kind='attempt'`，不动卡片、不改到期日。
而"今日到期"那个数是 `wordDao.dueWords()` 直接数库里的到期日的——**attempt 对它完全隐形**。
于是你老老实实测完一组 40 题，首页那个数字一点没动，明天它还在。
闸门本来是为了防"认出来"冒充"想起来"，结果顺带把"今天已经干过活"这件事也一起抹掉了。

## 决定

### 1. 「今天碰过」是一个单独的口径，不碰 FSRS

新加一个集合，只有一处定义：

```kotlin
// core/schedule/ScheduleService.kt
suspend fun handledWordIds(now: Instant): Set<Long> =
    logDao.handledWordIdsSince(LOG_SOURCE_QUIZ, boundary.startOf(now)).toSet()
```

SQL 是一句 `(kind = 'recall' OR source = 'quiz')`，按 `DayBoundary.startOf(now)` 取"今天"。
所以它收下三种记录：阅读页真记账的回忆、测验里答错的 `recall AGAIN`、以及**攒着还没满三次的 `attempt`**；
它不收 `kind='learn'`——光在读里第一次点开看过释义，不算"今天已经练过这个词"。

`pendingQueue(now, limit)` 用这份集合过滤 `todaysQueue` 的原始队列。凡是要回答"今天还剩多少事"的地方
一律只看这一份：**首页那个大字、每日提醒的文案、`dueCleared`（打卡与补卡）、室友连续天数**。
FSRS 一个参数没动，卡上的到期日一天没提前，`todaysQueue()` 那份**原始的**队列照旧供章节生成——
今天测过的词明天照样该在正文里复现。代价说清楚：测完之后"今日到期"能显示 0，而正文里那些词还是蓝的。
这不矛盾，因为两个数回答的是两个问题（"今天还要做什么" vs "这篇里我学到哪一步"），
而生成侧要的从来就是词表，不是待办清单。

**没有 Room 迁移**：`kind` 与 `source` 都是既有的 TEXT 列，只是第一次被拿来当"今天碰过"的判据。

### 2. 今日页两扇门：首测与补测是同一批词

- **今日测验**（`QuizMode.DUE`）＝今天到期或今天刚学过、**且今天还没碰过**的词。
- **今日复习**（新增 `QuizMode.REVIEW`）＝**今天测过一轮、但今天还没真记账地答对过**的那些词。

第二条的判据也是现读记录，两个集合相减：

```kotlin
// core/quiz/QuizService.kt
suspend fun reviewCandidates(now: Instant): List<WordEntity>  // quizzedWordIdsSince − recalledGoodIdsSince
```

`recalledGoodIdsSince` 是 `kind='recall' AND rating >= 3`——**沿用仓库里已有的"答对了"写法**，
不新造一个"毕业"标志位。于是这一格里：答错的词留着（它本来就欠一次）；只认出一次、两次的词留着
（还差次数）；连着认出三次升成一次真正回忆的词**自己下去**；一次都没碰过的词**根本不进来**（那是首测的事）。
一个词当天在首测就攒满三次毕业了，它不会在补测这格再出现第二次。
今天在阅读页学过、当天就测了的词也在这一格里——它的卡还没到期，但今天确实欠着两遍。

`EARLY` / `TRICKY` / `NEMESIS` 三个入口的闸门**一个字没改**（它们仍只认 `kind='recall'`，
所以当天毕业的词照样不会再来考你）。`REVIEW` 是第五个 `QuizMode`，而 `quiz_session.mode` 本就是 TEXT，
所以中途退出原位续做这条免费拿到，仍然**没有迁移**。

提前复习测的**不是**今天到期的词（它取学过、未到期的那一批），所以它不跟两扇门挤在一起，
自己一枚整宽胶囊；易错练习压到今日页最底下、隔开一整行——用户的话是"放在今日测验那里太容易误触了"。

### 3. 一个词一天内就能毕业

用户先把这条定死了：「一天内能攒满」——一次首测加两次补测，三次认出就在今天升成一次真正的回忆。
这一刀不做任何"每天只许攒一次"之类的限制，`RecognitionGate` 数的是记录、不是天数，本来就这样。

### 4. 压力数字摊开在明面上说

维持**每日新词上限 25**不动（用户：「三维持每日新词上限 25」）。摊开是：
每天首测 25 题 + 后续各 25 题 ≈ 一天 75 题；**今日到期在测完第一组之后立刻归零**，
而"今日复习"那一格始终挂着 50 个词等着补。这个不对称是设计的结果，不是 bug：
减掉的是"今天的待办"，留下的是"这个词今天还欠两遍"。界面不解释这个，解释写在关于页。

### 5. 结果页换皮，并且第一次有了第二个动作

旧结果页是几行纯文本 + 两个按钮，既不像 v3.9 之后其余四页，也没承担任何激励。新版：

- **一个主角**：`这组答对 12 / 40`——主色大圆角块 + 72sp 衬线黑体，与今日页那张主卡同一套皮（`app/ui/Capsule.kt` 之外唯一保留 30dp 大卡的地方，因为它是这一屏的主角）。
- 主角下面**一行小字**：最长连对、这一组让巅峰分涨跌了多少、破纪录——三件都是留底写完才知道的事，没算出来就整句不写。
- **没答对的词墙**：`没答对 8 个` + 那些词的词面排成 `FlowRow`（按字母序）。它比"有 N 个词答错"这句话直观，也正是下面那颗按钮存在的理由。
- **那颗按钮**：首测做完不再问"再来一组"，而是问「把今天测过的词再过一遍」→ 就地换成 `REVIEW` 那一组。
  补测做完还有词没过，同一颗按钮接着问一遍；过了（`left == 0`）才退回「再测一组」。
  `reviewCount` 是可空的：`null` = 还在数（这一秒不摆按钮，免得它一秒里换个意思），`0` = 真没词了。

关于「这组答对」这句话：v3.7 之后四选一答对只写一条 attempt，并没有真的记一次回忆，
所以按「文案只说真实状态」这条铁律，hero 写的是**答对**而不是"记住"。

### 6. 一个已知的竞态，不做处理

`answer()` 是异步写记录的，`finish()` 里紧接着读 `reviewCandidates()`，理论上最后一题那条可能还没落库，
于是这一格少算一个词。后果只是那颗按钮上的数字小 1、下一组少考一个词，明天它照样在首测那一格里出现。
为了它加一层等待或轮询，换来的是用户盯着一张结果页多卡半秒——不划算。

## 后果

- **测过一轮就"消失"是当天范围内的**：明天（或下一次到期日）这个词仍在库里等着，`attempt` 不动排期这一点没变。
  想让它真的走掉，只有连着认出三次或在阅读页真回忆一次——这正是用户要的分隔。
- 首页那个数与正文的蓝色可以不同步（见第 1 条）。这是有意的取舍，写进关于页而不是界面提示行。
- 「今日复习」这一格在重度日子会挂着 50 个词（上限 40 一组，可以再做一组）。
  它是可选的：不点它，今天照样算完成（`dueCleared` 在首测之后就清了）。
- `recalledGoodIdsSince` 用 `rating >= 3` 而非新加字段，所以历史上所有真记账过的 GOOD/EASY 立即生效，
  不需要任何回填。
- 关于页 `about_quiz_body` 补两段：减词规则、两扇门各考什么。`about_home_body` 第一句改了口径——
  它原先写「今日到期 = …和写下一章时交给 AI 的是同一份词表」，v4.1 之后这句不成立了（一份原始、一份减掉今天碰过的），
  现在明说「减掉的是"今天的待办"，不是这个词的排期」。易错练习那句从「不出现这一行」改成「不出现这一格」，
  「复仇」不再写「第四个入口」。界面里一个字都没多加。
- 版本号 4.1.0 / versionCode 28。
