# 0033 一页只有一个主角：删掉战斗力、巅峰分折成周对决、每组记一笔涨跌（v4.0）

## 背景

用户 2026-11-11 看完 v3.8 的战绩页：

> 「现在可以了，还有战绩那里有战斗力、段位、巅峰分不觉得有点乱吗，我觉得要不从 ui 入手，要不删掉一些，
> 还有之前我们说的那个影子对决那些事情，你打算怎么做。先和我讨论」

讨论之后把这一刀定死了两句：

> 「一步到位，每周 vs 上周，段位当主角，战绩每次测验后增减分都要写上。巅峰分也不要收起来吧，
> 想个展示的方式，能让两种都展示出来，但不突兀。」
>
> 「A＝巅峰分当唯一比分，段位继续当图里唯一主角、巅峰只放一行小字。」

还有一条是 v3.8 当面欠下的：`docs/adr/0030` 第 1 段末尾写着「影子对战与每周联赛另刀再谈」。
这一刀兑现它，而且只做"影子"那一半——对手仍然是以前的自己，不做联赛、不做排行。

## 决定

### 1. 战斗力整格删掉

`strength = 0.5 × 平均回忆把握 + 0.5 × 掌握占比`。它能说的那两句话，「此刻大概能想起」和「已掌握」
两张卡一边说了一半，那个 0–100 的数**不带一点新信息**，只是多抢一份视线——三个数同屏时谁都不是主角。

删的是字段本身（`RetentionReport.strength` 连同 `blank()` 一起去掉），不是"留着不画"：
留着就有第二处口径，下一刀就会有人拿它去排序。删掉之后这一页只剩两件事：一个称号（段位）、一个分（巅峰）。

### 2. 一页一个主角

- **主卡**：44sp 衬线的段位称号 +「升下一档还差 N 个词」，右上角一行小字「巅峰分 1098」。
  这就是"两种都展示出来但不突兀"的答案——称号是唯一的视觉主角，分只报数、不抢版面、也没收进折叠里。
- 主卡下面是那张「这周 vs 上周」，再往下才是两个小数卡（此刻能想起 / 已掌握）与「常忘的词」。
- **分享卡同一规矩**：主角是称号，巅峰最高分只在下面占一行小字（`share_card_peak`）。
- 正负号只有一处写法：`signed()` 挪进 `app/ui/NumberText.kt`（结果页、最近测验、周对决三处共用；
  feature 之间不许横向依赖，所以它在 `app/ui`）。

### 3. 影子对决 = 把同一条重放曲线按周折开，不建表

- `WeeklyDuel.of(events, weeks, thisWeek)` 读 `PeakScoreReplay.trajectory()`（重放途中**每一步之后**的分），
  按本地周分桶，各取这一周达到过的最高点。
- 周一为一周之始：`weekOf(epochDay) = (epochDay + 3).floorDiv(7)`（1970-01-01 是周四）。
  日子怎么折成"哪天"仍只由 `DayBoundary` 说了算，这一层不自建时区。
- 任一侧整周没有记录 → `null` → 界面写「—」并且**不说涨跌**。不拿起点 1200 冒充"上周打过"，
  那等于凭空给用户造一个可以打败的对手。
- `replay()` 一个字没改（历史最高那条别处还在读它），要每一步就另开 `trajectory()`。
- **取"这一周最高"而不是"周末最后一步"**：周日没碰词不该被判成这周打得差，一周的战绩在它最好的那一刻。
- 记录不足 20 次时整张卡不叫分，只说「只重放了 N 次记录，还不算分」——与战绩页别处同一个门槛。
- 为什么不建周表：`review_logs` 本来就是全量历史，重放一遍能算出任何一周。再存一张周表就是把同一个事实
  存两份，往后改一次重放参数就要担心旧周表算错。

### 4. 每做完一组，巅峰分的涨跌落一笔（Room v19）

- `PeakScoreReplay.groupChange(events, startedAtSec)`：把这一组**自己写下的**那些 recall
  （`source = quiz` 且 `epochSec >= startedAtSec`）从整段历史里抽掉再重放一次，两次相减。
  同一段时间里读小说记的账两边都有，减下来正好抵消，不会算成这一组的功劳或过错。
- 存的是**涨跌**（`quiz_runs.peakChange`，可空），不是这一组结束时的绝对分：绝对分任何时候重放都得出来，
  涨跌只有当时算得出——往后的记录一进来，那条曲线当时的形状就再也回不去了。这一列进 v19 只为这一个数。
- `startedAtSec`（这一组开始出题的那一刻）跟着 `quiz_session` 的 JSON 存成**带默认值的可选键**，
  旧存档解成 0；`QuizRunRecord` 多带这一个字段，不动表结构之外的东西。
- **三种"这一笔不算"**：记录不足 20（这个分本身就没有意义）、`startedAtSec = 0`（v19 之前留下的会话，
  不知道从哪一秒开始）、这一组一条真记账都没写（全被认出闸门攒成 `attempt`，没资格动分）。
  前两种是 `null`——界面那一行干脆不写；最后一种是**真的 0**，写「巅峰分 +0」。
- 所以这一列**必须可空**：默认 0 会把"没算过"读成"这一组不痛不痒"。`QuizRunMigrationTest` 锁住老行是 NULL。
- 界面两处：结果页多一行「这一组巅峰分 +7」（和破纪录同一个时机，留底写完才知道，晚一步出现）；
  「最近测验」每行第三小字「巅峰分 +7」，负数走铁锈红。徽章与这两处一律写全「巅峰分」——
  验收时主卡那行只写「巅峰 1133」，压在对决卡「上周最高 1342」上面读起来像自相矛盾。

### 5. 字要少

周对决怎么折的、为什么上周没记录就不说涨跌、那一笔涨跌什么时候不写、为什么没有战斗力了——
全部写进关于页 `about_stats_body` / `about_quiz_body`。主界面只给数。

## 后果

- Room 到 **19**：`ALTER TABLE quiz_runs ADD COLUMN peakChange` 一句，不建表、不建索引，
  所以 `SyncFingerprint` 那 20 张表一个字都不用改，这一刀不会让同步多问一句「本机又动过」。
  迁移测试是 `QuizRunMigrationTest` 的 v18→v19（老行留空）+ v1→v19 全链。
- 战斗力从三处消失：`RetentionReport`、战绩页、关于页文案。老用户回头找不到那一格，是这一刀想要的效果。
- 巅峰分第一次有了"周"这个尺度：以前它只有当前值和一个历史最高，读不出这一周比上一周好还是差。
- `peakChange` 只从 v19 之后做的那些组开始有，此前的成绩永远留空——**不回填**，
  因为拿着今天的整段历史算不出当时那一条曲线。
- `QuizRunStore` 从此需要 `ReviewHistoryDao`：算这一组的涨跌要读全量历史。它仍只在写那一行时读一次，
  不写 `review_logs`，战绩页那一栏照旧只读。
- 没做的：每周联赛、排行榜、把别人放进对手位。影子对决只兑现"跟自己比"这一半。
- versionName 4.0.0 / versionCode 27；**待真机验收**。
