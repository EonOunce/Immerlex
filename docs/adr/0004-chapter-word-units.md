# ADR-0004: 章是阅读单位，词是调度单位

- 状态：已采用
- 日期：2026-10-28

## 背景

真机跑通生成后暴露出一个从未明说的含糊：复习的"一次完成"到底算一章还是算一个词。当时的实现两种都不完全——`ReaderViewModel.load()` 只取 `latest(genre)`，读完一章、再生成下一章，旧章就在界面上永久消失（库里还在，眼睛进不去）；而 `grade()` 每点一次词就 `ScheduleService.review()` 一次并写一条 `review_logs`，同一章里把 meticulous 连点五次，FSRS 会收到五次 `elapsedDays=0` 的"合格复习"，stability 被往上拽，间隔从此偏长。词在旧章里未打分的状态也随旧章一起不可达。

用户给出的需求全部是行为层面的：小说能继续生成、旧章节能回看、手滑重复点击不能多算复习、点错评分可以修改、先不认识学过后认识要能记录学习过程；并且明确不接受"因为上次点了不认识，就允许接下来随便连点不断累加复习次数"。

## 决定

1. **章 = 阅读单位，词 = 调度单位。** 一个词的到期状态全库唯一，跨章共享：这个词在第 3 章被评分，就清掉了它这一次到期，第 8 章再复现时它已是未到期的正常阅读文本。生成下一章不得让任何旧章失去阅读与打分的能力。
2. 阅读页标题变为章节切换入口（同题材本章列表），不新增书架页；退出重进一律回最新章。
3. **计分的三条规则**：未到期词只揭示释义、不计分，也不显示打分按钮；到期词打分算一次复习，同日同词第二次提交是**修改**最后一条记录而非新增；同日同词封顶 2 条——"不认识"紧接"学回"算两次（真实的学习过程），第三次点击继续走修改分支。
4. 支撑第 3 条的前提：`review_logs` 记录**评分前**的卡片快照（stability / difficulty / state）。修改评分时先用快照把词退回评前状态，再按新评分重算并覆盖该条记录。选择存快照而不是"删掉该词全部日志重放"，因为重放要求 FSRS 参数集永不变、且新词初始状态只能靠 `createdAtSec` 反推，任何一点偏差都会污染历史。
5. 幂等边界按 FSRS 的 `due` 判，不按本地自然日判——自然日既漏掉 23:50/00:10 连点，也会把"提前几天复习"错当重复提交。上一条是"不认识"时放行第二次，其余一律修改而非追加。
6. 章节管理：**重写本章**（同一批词重新生成，编号不变，旧内容替换）与**删除章节**。删章只删文本，**不碰任何词的复习状态**——那是第 1 条的直接推论。重写要弹确认，因为它是另一次 API 花费。
7. 章节编号继续取档案与章节表的较大者 +1（已于 ADR-0003 第 4 条落地，此处只是承接：删掉最新章后编号会回落到 `max+1`，不会出现空洞或重复）。

## 后果

- 手滑与"提前复习"不再污染调度参数；改错分可精确回退，不产生历史记录膨胀。
- Room schema 变更（`review_logs` 加列 + 可能的章节管理列），必须写 Migration 与迁移测试，禁止 destructive。
- `ReviewLogDao.deleteForWord` 从"未使用"变成删词连带清理的既有依据，但**不**用于回滚评分——回滚走快照。
- "重写本章"意味着同一批词可能连续两次向模型要稿，失败重试（最多 3 次调用）的成本要计入确认文案。
- 旧章回看时，未到期的词点下去只出释义卡片。用户若想强行复习只能等到期——这是有意选择，用可控性换掉刷分空间。
- 升级当天有一次性缺口：v1 的 `review_logs` 行没有评前快照（迁移用哨兵值标记），所以**升级当天已复习过的词不能改分**，卡片退化为"只揭示不计分"，次日自然消失。不回填猜测的快照值：猜错的 stability 会一路污染后续所有间隔。
