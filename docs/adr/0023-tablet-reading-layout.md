# 0023 平板上的阅读页与室友页（v3.0）

## 背景

用户在平板上用这个应用，原本所有页面按手机单列拉伸：阅读页正文一行塞进八九十字，
找不到下一行的开头；室友房间被拉成一条走廊。产品不需要"平板专用版"，只需要在这些
页面上**别把内容摊满屏**。

## 决定

1. **窗口只分四档**，阈值沿用 Material 的 600 / 840 / 1200dp（`app/ui/WindowClass.kt`）：
   `COMPACT < 600 ≤ MEDIUM < 840 ≤ EXPANDED < 1200 ≤ WIDE`。不引 `material3-adaptive`，
   分级本来就是一个纯函数，写成 `windowClassOf(widthDp)` 还能单测。
2. **阅读页按宽度摆栏**（`feature/reader/ReaderLayout.kt`，纯函数 `readerPanesOf`）：
   - 手机：保持原样——词卡是底部抽屉，章节目录是标题旁的下拉；
   - ≥600dp：章节目录单独成左栏（`READER_CHAPTER_RAIL_DP = 224`），标题不再兼作目录入口；
   - ≥1200dp：词卡再挪到右栏（`READER_CARD_PANE_DP = 344`），不再盖住正文。
   正文栏最宽 `READER_BODY_MAX_WIDTH_DP = 720`，居中。1200 这个门槛是按"正文还剩约
   600dp、一行三十来字"反推的，不是随手取的。
3. **右栏的宽度一直占着**（词卡没开也占位）：词卡开合时正文不重新折行，刚点过的词不跳。
4. **室友页内容限宽 720dp 居中**（`ROOMMATE_MAX_WIDTH_DP`），房间与气泡不再横向拉长。
5. 底部四个入口在平板上仍是底部栏，不改成侧边栏——这是"别摊满屏"而不是"重做导航"。

## 后果

- 手机上经历的所有交互一字不变；平板上阅读从"通栏排版"变成"目录 + 正文 + 词卡"三栏。
- 三档宽度各有自动化测试（`ReaderLayoutTest`：599/600/839/840/1199/1200 边界、
  手机保持抽屉、平板先有目录后有词卡、1200 时正文仍有 ≥600dp）。
- 模拟器用 `wm size 2560x1600` + `wm density 240` 验收过 1706dp（三栏）与 800dp（两栏），
  复位后手机布局与原来一致。
- 其它页面（词库、设置、今日、易混词）仍是拉伸布局；要改时沿用同一个分档函数，
  不再各写一套阈值。
