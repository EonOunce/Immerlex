# 0024 搭配题只作为一种题型（v3.2）

## 背景

用户要求覆盖考研红宝书全量词，并早先明确：**搭配不是一个独立的复习单位**，最多作为
一种新的问法出现在测验里。一个词始终只有一张 FSRS 卡，这是 ADR 0012 定下的边界。

难点在数据：素材包原先只有释义、例句、易混池，**推不出可靠的真实搭配**。若拿例句里的
动宾片段或易混词硬凑，搭配题会拿一个根本用不上的短语当正确答案，比没有这道题更糟。

## 决定

1. **素材包新增可选字段 `collocations`**：`[{"en":"take measures","zh":"采取措施"}]`，
   也认纯字符串与 `phrase/gloss/translation` 等别名；每条最多 4 个、释义截到 60 字。
   校验只有一条硬规矩：**短语必须真的包含这个词**（`make progress` 不能挂到 `take` 名下），
   且比词本身长。不合格的条目在导入时丢掉，不回填、不猜。
2. **新增 `QuizType.COLLOCATION("COLLOCATION", tier = 2)`**：与释义选词同为最高档，
   要中→英答对过才解锁；易错词不分档，五种全开。题型只决定怎么问，不新建排期、不改 FSRS。
3. **`CollocationBuilder`**：题干是这个词自己的**真实短语**（`take measures`），问"选出这个短语
   的意思"；四个选项都是中文释义，每个选项的另一面（`gloss`）是它对应的英文短语，答完就地揭开，
   与 v2.5 "选项自带另一面"同一个规矩。正确项**只从这个词自己的搭配里取**，按 `attempts` 轮换；
   干扰项从同词的其他搭配与**别的词**的搭配池里抽，滤掉与本词短语重名、与正确答案文字重名、
   任一面为空的条目，再按文本去重。没有搭配材料的词直接不出这道题。

   **为什么不反过来问**（原来那版是"题干 = 单词，选项 = 英文短语"）：那样四个选项里只有正确项
   含题干那个词，用户凭**子串就排除掉三个**，题等于白送。改成"短语 → 释义"之后四个选项都是
   真实存在的搭配释义，没有一处是现编的——早先考虑的"把搭配里的中心词换成别的词造干扰项"
   会同时踩两条线：编造数据，且可能造出碰巧也成立的短语（`make a decision` → `make a plan`），
   那就不只是坏干扰项，而是把错答案判成对的了。
4. **存储**：Room v16 给 `quiz_material` 加 `collocations TEXT NOT NULL DEFAULT '[]'`
   （与 `distractors` 同一种 `[{"w","zh"}]` 编码，`MaterialPool` 一份编解码）。
   老行留空列表：搭配题对它们不可用，不拿别的字段凑。
5. **合并**沿用 fill-only：包给了搭配就整池换，没给就留住旧池；只写短语的条目由 ECDICT
   补释义，补不上丢掉。
6. **不问 AI 要搭配**：`EnrichedWord.collocations` 只从素材包来（`QuizEnricher` 不产生它）。

## 后果

- 有搭配素材的词在最高档多一种问法；没有的词什么都不会发生（题型静默不可用）。
- 搭配的干扰项来自同一个词的其他搭配与同组其他词，所以搭配题天然需要素材覆盖面够宽；
  词少时选项会变少，凑不出一个干扰项就整题不出（宁可不问，不摆一个只有正确项的题）。
- 搭配题考的是"认不认得这个短语"，不是"这个词的意思"——所以它和其它四种题型答的是两件
  不同的事，但记的是同一张卡的同一档评分（ADR 0012）。
- 配错行的短语（不含该词、比词还短）在导入时就刷掉并**单独报数**
  （`PackRead.badCollocations`），用户拿这个数字回去找生成方改包；只是写重了的不算错。
- 词典卡与词库搜索结果显示搭配，用户能看见"这个词素材包里到底有什么"。
- 相关测试：`QuestionBuildersTest`（题干是真实短语、四个选项都是释义、没有选项靠子串就能排除、
  轮换、空释义不可用）、`MaterialPackTest`（含词校验 / 去重 / 截断 / 配错行报数 / 导出回读）、
  `MaterialMergeTest`（整池换 / 空池保留 / 字典补释义）、`QuizPolicyTest`（档位）、
  `QuizServiceTest`（素材行 → 搭配题）、`QuizMaterialStoreTest`（存取回环）、
  `QuizMaterialCollocationMigrationTest`（v15→v16、v1→v16 全链）。
