# ADR-0006: v1.0 日常化层——今日任务页、通知、坚果云 WebDAV 自动备份

- 状态：已采用
- 日期：2026-10-28

## 背景

生成链路跑通后，产品的缺口不再是"能不能写出章节"，而是"用户凭什么每天回来"。同时数据安全性是裸的：词库靠 OCR 与手工导入攒起来，复习进度跨月累积，全部只存在于手机里一份 SQLite；而词库页的删除会连带删掉该词全部复习记录，没有撤销。`feature/home` 原本排在 v1.5，用户 2026-10-28 明确要求提前到 v1。

数据量实测：4 词 2 章的库文件 53KB，正文内容只占约 3KB；外推到重度一年（3000 词 / 400 章 / 3 万条复习记录）约 5MB，gzip 成单份备份约 1.5MB，每日传一份约 45MB/月。坚果云免费版 WebDAV 第三方应用通道每月上行 1GB、下行 3GB，单文件 500MB，请求频率每 30 分钟 600 次——余量极大。

## 决定

1. **`feature/home` 成为底部第四栏**，承载今日到期数、今日已完成数、连续天数、"开始今日阅读"入口。今日页所需的数字全部从现有 `words.dueEpochSec` 与 `review_logs` 推导，不复制一份"还剩多少词"的算法到别处——阅读页头部与今日页必须共用同一个来源。
2. **打卡门槛取低**：当天给任意 1 个词打过分即算打卡。漏一天不归零；次日清空当日全部到期词即自动补上昨天，每周最多补 1 次，今日页要显示"本周补卡：未用/已用"。
3. **明确不做积分与兑换补卡券**。补卡券与本决定第 2 条解决同一个问题，却要多一套货币、定价、余额与兑换记录；更关键的是把外部奖励挂在"打分"动作上，会给"制造复习次数"提供动机，与 ADR-0004 的防刷规则直接互相拆台。若日后确要奖励层，兑换物必须是"更多的内容"（题材、每日新词上限、周报），不能是"免于惩罚"。
4. **通知两件事**：每日到期提醒（默认 20:30，可改可关，当日到期为 0 时不发）；生成超过 10 秒挂进行中通知，完成后转为"第 N 章已写好"。文案只允许陈述真实存在的状态，"该读第三章了"这类话在章节状态做出来之前不许写。Android 13+ 需 `POST_NOTIFICATIONS` 运行时授权。
5. **备份走坚果云 WebDAV，明文、不加密**。流程固定为：数据库一致性快照 → gzip → 上传，**禁止**把正在写入的 SQLite 文件直接交给同步通道——数据库文件在写入过程中处于中间状态，半途失败就是一份云端损坏的库。
6. **版本回溯自己实现**：坚果云 WebDAV 没有服务端版本历史，因此备份文件按日期命名铺在同一目录，云端保留最近 30 份 + 每月最后一份，旧的自动删。恢复侧列出日期、选中、校验（gzip 头 + 表结构 + 行数）通过才允许覆盖本地库，失败必须明说而不是静默换库。
7. **AI key 不进备份**。密钥单独存在于 EncryptedSharedPreferences，备份文件只含学习数据；因此换机恢复后必须重填 baseURL / key / model 才能生成——这一点要在恢复完成的那一刻明确告知，否则用户会误判备份失效。
8. 坚果云凭据用**应用密码**（非登录密码），与 AI key 同一套 EncryptedSharedPreferences 存储；WebDAV 地址预填 `https://dav.jianguoyun.com/dav/`，沿用 AI 网关预设的做法（预置可选、不强迫手填）。
9. 自动上传交给 WorkManager 每日一次 + 设置页"立即备份"按钮，不引入新的常驻服务；请求频率远低于坚果云每 30 分钟 600 次的上限。

## 后果

- 新增依赖（WorkManager）、新增通知渠道与运行时权限、新增 Room 表（每日打卡记录）——schema 变更与迁移测试随 v1.0 一并做。
- 备份文件是明文，含词库、章节与题材/AI 服务地址（不含 key）。风险面是坚果云账号本身；换取的是"永远不会因为忘口令而备份作废"。用户 2026-10-28 明确选明文。
- 云端保留 30 份 ≈ 45MB 占用（流量额度不返还删除的部分，但删除不再消耗上行）。
- 定时备份需要网络与前台可见性之外的后台执行，失败必须可见：设置页显示"上次备份：今天 21:03 / 失败：账号或密码不对"。
