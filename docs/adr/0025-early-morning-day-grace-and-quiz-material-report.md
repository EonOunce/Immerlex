# 0025 凌晨宽限与测验素材账（v3.3）

## 背景

用户提出两件事：

1. **测验准备时要说清素材从哪来**：一组词里多少已经有出题素材、多少还要问一次模型。
   之前加载页只有"正在请求 AI 出题"，配了 key 也不知道这一组会不会真的发请求、发几个词。
2. **一天不该在零点硬切**：当天背过词、但到期词还没清完，零点一过今日页就翻页，
   剩下的词被算到"明天"；用户熬夜到 00:30 时希望这仍算前一天。反之，
   当天没背词、或者到期词已经清完，就该零点翻页，不该白送一段宽限。

## 决定

1. **`core.schedule.DayBoundary` 成为"今天是哪一天"的唯一判定**，今日页
   （`DailyLoopService.info` / `todayTally`）、测验候选（`QuizService`）、
   阅读页"今天回忆过"（`ReaderGrading`）都经它取当天起点，不再各写一份零点。
   - 00:00–00:59 之外：就是日历日。
   - 00:00–00:59：只有**昨天在 01:00 以后有过复习**、且 `daily_loop` 里昨天
     `dueCleared` 不为真，才把"今天"仍算作昨天；否则照常翻页。
   - 只认 01:00 以后的记录，防止"每天 00:30 背一点"把日期一天天粘住；
     清完到期词后 `info` 会写下 `dueCleared`，下一次加载就立刻翻页。
2. **热力图与 30 天趋势不跟宽限走**：它们按日历日画格，00:xx 的记录仍然点亮当天那格，
   不会在 01:00 后突然把颜色挪到前一天。宽限只影响"今日"这一桶和连续天数。
3. **测验加载页显示素材账**：`QuizMaterialPrep(ready, toAsk, canAsk)` 由
   `QuizService` 在读素材表之后、真正发请求之前报给界面，三句文案分别对应
   "全部已有 / 还要问 AI / 没配 key 没有素材"。`QuizEnricher.available()`
   让没配 key 的设备说"没有素材"而不是替 AI 承诺一次请求。
   这行字只解释准备过程，不参与记账、不改变出题。

## 后果

- 凌晨 00:00–00:59 学到的词算前一天：连续天数、今日新学/回忆、分享卡词墙、
  今日到期提示都归到同一天；清完到期词后马上恢复零点翻页。
- "昨天在 01:00 后动过手"需要一次 `review_logs` 范围查询；只有宽限小时内才查，
  白天零开销。没有新增表、没有 Room 迁移。
- 凌晨宽限里没学也没清到期词时，日期不动、连续天数也不会因为跨了零点而多算一天——
  打卡仍以"当天有任意学习/回忆记录"为准。
- 素材账是界面层信息：素材表已有该词就计入 ready，不再问模型（ADR 0017/0022 的
  "一个词只问一回"不变）；`toAsk == 0` 时根本不进入 `ASKING_AI` 阶段。
- 相关测试：`DayBoundaryTest`（未完成延到 01:00、01:00 结束、清完即翻页、没学不延、
  仅 00:30 记录不粘连）、`DailyLoopServiceTest`（凌晨记录算前一天、宽限中清完翻页）、
  `QuizServiceTest`（素材已有/待问计数、无 key 不承诺请求）。
