# 0039 收起窗口那颗键，与连连看的整屏牌面

## 背景

用户 2026-11-22 提了三条，都来自"在课上用三星平板开小窗偷背"这一个场景：

1. 「有没有办法通过键盘的一个快捷键，让这个软件或者定制一个全局快捷键，让小窗最小化，就是只变成一个图标悬浮在屏幕上」；我一度提议自己画一颗悬浮球（`SYSTEM_ALERT_WINDOW`），用户当场否掉：「你这个不能直接用三星平板的小窗功能吗，三星小窗本来就可以缩成一个图标」——那颗球、那个权限、以及"从后台把 Activity 拉回来"的顾虑一起作废。
2. 「你应该让连连看平均分布在整个屏幕上，而不是只集中在上方」——v4.4 的牌面挂在一个 `verticalScroll` 的 Column 顶部，五张牌各 58dp，2400px 高的屏上只占了上面三分之一，下面一整片空。
3. 「连连看有没有办法通过按键的方式进行」，并自己定了形状：「那就直接只按1-5，第一次按代表按左边的，第二次按代表按右边的，如果第一次按完按了6，那就代表撤销这次选择」。

## 决定

**1. 「收起窗口」是一个键位动作，不是一个悬浮球。**

- `KeyContext` 多出第三个值 `GLOBAL`（不分页面），`KeyAction.APP_HIDE` 默认 `KEYCODE_ESCAPE`（阅读页与测验页都没占它）。它是键位页「键盘快捷键」里唯一的新条目：多一组「全局」，组里一行「收起窗口」。
- 收起的动作只有一份写法，在 `app/ui/HideWindow.kt`：`hideWindow(context)` = 把 Context 拆到 Activity 再 `moveTaskToBack(true)`，整个窗口交给系统——三星的小窗自己会缩成一颗可拖动的图标，点图标就回来。**我们不申请任何权限、不画任何东西、也不负责"回来"**：回来是用户点那颗图标，所以 Android 10+ 的后台启动限制与这件事无关。
- 拦在两处，因为按键只送到有焦点的那扇窗：
  - `MainActivity.onKeyDown` 管常规页面——拦在 Activity 这一层而不是界面里的焦点捕获，任何一屏都收得到，不会因为此刻焦点落在某个按钮上就漏掉。**这里是 `onKeyDown` 而不是覆写 `dispatchKeyEvent`**：`ComponentActivity.dispatchKeyEvent` 带 `@RestrictTo`，覆写它 lint 直接报 3 条 `RestrictedApi` error（这一版就是这么被拦下的）。
  - `app/ui/Keyboard.kt` 的 `KeyCapture` 里认同一颗键——抽屉与弹窗是另一扇窗，按键根本到不了 Activity。所以阅读页的词卡抽屉（`WordCard.kt` 本来就包了一层 `KeyCapture`）也收得到。
- **诚实的边界**：`AlertDialog` / `Dialog` / `ModalBottomSheet` 里没有 `KeyCapture` 的那些窗口收不到这颗键——词典卡、分享预览、词库的各种弹窗、室友小铺。要收先按返回把它关掉。给每个弹窗都塞一层焦点捕获不值得：它们都是用户自己刚点开的一层皮，不是"正在背单词"的那一屏。这一句写在关于页「关于键盘」里。
- `KeyRecording`（`core.settings`，一个 `@Volatile` 布尔）：键位页正在录一个键时，这颗键必须让路。收键是在 Activity 那一层拦的、比界面先看到按键，不让路的话想把别的动作绑到 Esc 上，一按 Esc 应用自己先收起来了，永远绑不成。`KeyboardScreen` 用 `SideEffect` 跟着 `capturing` 置位、离开页面复位。
- 窗口退到后面时朗读立刻停：`WordSpeaker.stop()`（只闭嘴、不拆引擎，回来还能接着读）+ `rememberWordSpeaker()` 里一个 `LifecycleEventObserver`，`ON_PAUSE` 就停。界面藏着而声音还在教室里，比界面露着更糟。

**2. 连连看的牌面摊满整屏，宽屏限宽。**

`PlayBody` 改成 `BoxWithConstraints` 里两条路，判据只有一句：这一屏的高度够不够摆下「进度行 + 五张 58dp 的牌 + 间距」。

- 够（手机与平板的正常高度）→ 不滚动：外层 Column 占满高度，牌区 `weight(1f)`，每张牌在列里 `weight(1f).heightIn(max = 140.dp)`，列的 `Arrangement.spacedBy(gap, Alignment.CenterVertically)` 把长到 140dp 之后多出来的空当上下均分。牌是**摊开**的，不是拉长的。
- 不够（三星小窗收成半屏、横屏手机）→ 退回原来的滚动，牌仍按 58dp 起步。
- 两条路共用 `MatchColumn`，牌面高度只在 `fill` 这一个开关上分岔。
- 牌区限宽 720dp 居中（`MATCH_BOARD_MAX_WIDTH`，与阅读页正文同一个数）：摊到平板两头，眼睛就得来回扫一整屏。
- **踩过的一个坑（写在这是因为它会再犯）**：第一版把牌面高度写成外面传进来的 `(Modifier) -> Modifier`  lambda，那个 lambda 是在 `Row` 的作用域里建的，于是 `it.weight(1f)` 编到的是 `RowScope.weight`——挂到 Column 的子项上 ParentData 没人认，牌会静悄悄地塌回 58dp，编译与预览都不报错。`weight` 必须在它自己那个 scope 里写，所以改成传 `fill: Boolean`、由 `MatchColumn` 在自己的 `ColumnScope` 里加 `weight`。

**3. 连连看的数字键就是这一屏的五个位置。**

- `1–5` = 这一屏从上到下的五对；**按的是"另一边"**：没选中时按左边、已选左边时按右边、已选右边（先用手指点过右边那张）时按左边。`6` = 把刚才点的那张放回去（新的 `MatchViewModel.cancelPick()`，只清 `pickedSide/pickedId/wrongIds`）。不在 PLAYING 阶段、或这一屏没有第 N 对，那颗键就当没按过（返回 false，不吞）。
- 这几颗键**不进设置页、不进 `KeyAction`**：它们不是"哪个动作绑哪个键"，就是这一屏的五个位置，跟四选一的 `1–4` 选 A–D 一样是玩法本身。绑定了反而会有"我把 3 改到别处，牌就数不对了"这种说不通的状态。
- `KeyCapture(requestOn = state)` 包住整页，换屏、换选中都重抢一次焦点。收起窗口那颗键在 `KeyCapture` 里先认，所以这一页两个都灵。

**没有 Room 迁移、不动任何数据、不申请任何权限。** 新字符串只有 `key_global_section`（全局）、`key_app_hide`（收起窗口），加上关于页「关于键盘」里的三段说明。

## 后果

- 收起窗口这件事在模拟器上只能验一半：`moveTaskToBack(true)` 在模拟器上等于回桌面，窗口确实走了、点图标确实回来；**三星会不会把它折成那颗小窗图标，只有用户那台平板能验**。折不成的话改的是 `hideWindow()` 这一个函数（备选是发一个 HOME intent），不是这套键位。
- 收起时正在读的那个词会停在半句，回来不自动接着读——`stop()` 只闭嘴，不重播。这是有意的：教室里"再读一遍"比"读半句"更糟。
- 连连看在 5 对满屏时牌面最高 140dp、字仍是原来那两个字号，所以牌看起来更空而不是更大；一屏只有 2–4 对时（尾屏）牌同样按份分，会比满屏那几屏更高，这是均分的自然结果。
- 数字键与手指可以混着用，但**配错的代价是真的**：先按 `3` 点了左边、再按 `4`（而不是 `3`）就是配错一对，这一对在这一组里不再计分。唯一的退路是 `6`，而 `6` 只在还没按下第二张之前有用——这条写在关于页里，界面上不提示。
