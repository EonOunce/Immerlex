# 0036 — 测验答完之后，再点一下选项区就是下一题

日期：2026-11-15 · 版本：v4.3.0（versionCode 30）· 无 Room 迁移

## 背景

v2.5 定下「每个选项自带另一面」：答完就地掀开——中文选项下面露它的英文，英文选项下面露它的释义。
v4.1 又把结果页做成一个主角，但**答题那一屏**没动：题干卡 + 四张选项卡 + 翻开后新增的
「答对了 / 算没记住」+ 可能一句「标为易错」+「下一题」按钮，全排在同一个 `Column` 里。
于是**答完那一下，版面自己长高**，`下一题` 被推到要划一下才够得着的地方——用户真机反馈
「按了选项，出现一些文字会把选项撑大，甚至把下一题都移到了要再划一下才能按的程度」，
要的是「无脑一点，不需要太多操作就能刷题」，并自己给出了形状：
「我想的是选完之后再点一次选的地方，就能下一题」。

别的刷题软件（Anki、不背单词、墨墨）都是**点屏翻页**：反馈印在同一屏上，手势落在整片内容区，
从不要求手指去够一颗按钮。这里缺的只是那层可点的区域。

## 决定

1. **答完之后，整片选项区就是「下一题」**：四张选项卡本身、卡与卡之间的缝都算。
   未答时照旧——点卡=作答，一次点击只可能做一件事。
   实现在 `feature/quiz/QuizQuestionBody.kt`：选项外面套一层 `Column(clickable(enabled = state.answered) { onNext() })`
   管住卡缝，`OptionCard` 自己按 `clickable { if (answered) onContinue() else onPick(index) }` 管住卡面。
2. **卡片必须自己接这一笔**。`clickable(enabled = false)` **不会**把点击交给祖先那层——
   第一版只加父层 `Column`，实测点卡面一点反应没有、只有点卡缝才翻页。所以旧的那个
   `enabled = !answered` 写法要换成按状态分流，而不是禁用。
3. **什么都不动**：选项的另一面照样掀开（v2.5 那条要求原样保留）、`下一题 / 完成` 那颗按钮留在原地当退路、
   `标为易错` / `移出易错` 在选项区外面不受影响、键盘 `→` 照旧、记账与排期一个字没改。
   `QuizViewModel` 的两道闸门本来就挡住了误触：`answer()` 遇 `answered` 直接返回，`next()` 遇未答直接返回。
4. **不加防抖**。连点两下会跳一题，这和键盘那条「答完只认右键，免得连按把下一题也点掉」是同一件事；
   但键位要防的是**按住不放产生的自动重复**，而手指翻页必须抬手再按——那是明确动作。
   加了防抖反而让正常的第二下像被吞掉，与「无脑刷题」相反。真机上若确实误跳，改的是这一句，
   不是撤掉手势。

## 后果

- 手指停在选项上就能一路刷完一组，不必每答一题去找一次按钮，也不必 scroll。
- 一次点击只翻一题：子节点吃掉点击后父层收不到，模拟器上逐题核过（5/15 → 6/15 → 7/15，没有跳过题）。
- 三种翻页入口并存（卡面、卡缝、按钮）+ 键盘，同一时刻只有一个是"必答的那一步"，语义不冲突：
  答错的最后一题按钮写「完成」，点选项区照样走到本轮末尾的重练；重练那一段同样能点选项翻页。
- 中途退出原位续做后，**已答状态复原时也能点选项翻页**（`state.answered` 从 `quiz_session` 读回来，
  这一层只看这个布尔），实测杀进程重开后续做正常。
- 纯界面改动：不动数据、不动口径、**没有 Room 迁移**、不加字符串；451 + 1 项 JVM 单测与 lint 结果与 v4.2 相同。
  手势本身在 Compose 里，本项目没有 Compose UI 测试框架，所以这条只在模拟器上实走锁住。
