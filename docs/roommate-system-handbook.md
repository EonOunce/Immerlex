# 可复用 AI 室友系统工作手册

版本：讨论交接稿 1.0 · 2026-10-29。面向接手实施的 AI 与开发者。

## 0. 如何使用本手册

这是一份产品约束、控制算法和分阶段实施契约，不是已上线功能清单，也不是一条发给大模型的长提示词。用户已授权制作手册，未授权据此直接改造任意软件。

- 在其他软件中使用：复制本文件，先填写第 3 节宿主适配表，再执行第 13 节阶段 0；不需要词间代码、FSRS 或 Android。
- 在词间中使用：同时读 [词间接入附录](roommate-immerlex-integration.md) 和 [决策变更记录](adr/0014-roommate-system-and-learning-rewards.md)，再读仓库现行工作规范。
- 与用户沟通时只讲“做什么、看到什么、之后怎样”；编程实现由执行者负责，涉及重要架构或授权时再解释体验取舍。
- 本文的“确定”来自用户明确认可；“建议”是允许制作演示的起点；“待确认”不可伪装成定案。
- 遵守宿主安全、隐私、迁移和发布规范。不覆盖既有改动，不擅自提交、推送、清数据或升级真实设备。

## 1. 产品目标与已确认边界

目标：用户完成宿主中的真实活动，为一个同住小室友带来生活素材与可消费奖励；室友有自己的工作、朋友、偏好、创作和小计划，与用户形成持续共同记忆。

确定的体验：

1. 陪伴、养成装扮、生活惊喜都需要，优先级最高的是生活与惊喜，不是分数增长。
2. 室友会自己出门、打工、交朋友；既可回来讲见闻，也可询问意见、邀请参与，不限于每日一段故事。
3. 初次相识由用户选择性格维度，再生成具体性格卡。性格有稳定底色，兴趣、习惯和关系随经历变化。
4. 宿主活动的“内容”影响生活素材，“数量”可以影响奖励和少量支线，但不能强迫用户刷活动才能得到结局。
5. 普通陪伴免费。用户可赚货币、送礼物、购买室友的创作；赠品不限实物，也可有口头禅、微个性。
6. 新习惯和动作也可由活动内容或室友自主经历免费习得，不得全部锁进商店。自主习得频率必须由可测试函数控制。
7. 礼物会产生后续：送吉他后会练习、找搭档、筹备演出；不能仅有一次感谢动画。
8. 室友有自己的主见，用户建议不是每次都被机械执行。可有与用户不同的看法，但不羞辱、威胁或操控用户。
9. 可有一两件共同小计划；用户不处理时，普通生活继续，不堆积成一串强制待办。
10. 存档保存人物、关系、经历、选择、习惯、资产与进度，能备份并在另一台设备接续。

禁止：以用户漏学为理由扣钱、清空关系、病死、离家出走；让室友制造虚假学习记录；靠连点刷奖励；模型自行发币、扣币、改冷却或创建不存在的美术资源。

## 2. 一天的完整体验与内容边界

建议的演示流程：

- 第一天：选择性格，认识室友；完成宿主活动，获得货币。普通摸头、问候、看近况不收费。
- 第二天：打开看到室友正在做与近期内容相关的事情，听一小段见闻；可能收到一个提问，不必答完才能使用主软件。
- 随后几天：用户送礼或给建议，事情逐步发展；旧人物、小物件、口头禅再次出现，形成只有彼此懂的梗。
- 偶尔：室友摆摊售卖自己的短故事、观察手记、谜题或原创菜单；作品可实际打开，不是只有商品名的空收藏卡。
- 长期：反复发生的行为才可能成为习惯。换设备后仍认识同样的人、保留余额和未结束的事情。

分清三种变化：

| 类型 | 例子 | 控制方式 |
|---|---|---|
| 即时表演 | 喝一口茶、惊讶、摸头回应 | 可反复使用已有动作，不算习得 |
| 一次生活事件 | 在雨天第一次尝试泡茶 | 事件节奏与内容去重 |
| 稳定习惯 | 后来下雨时常会泡茶 | 证据积累与习得函数 |

现有动作多不等于新习惯多；暂停新增习惯时，已学会的动作和日常故事仍正常出现。

## 3. 可复用边界：宿主适配，不重写宿主

原则：复用领域规则、协议和测试；不是现在就开发通用 SDK、插件市场或跨平台同步服务。只在实际接入第二个软件时抽取有真实需求的共享代码。

每个宿主先填下表，未填完不得接入真实收益：

| 配置项 | 必须回答的问题 |
|---|---|
| 活动源 | 什么真实完成的行为可计入？查看、预览、重练哪些不算？ |
| 单位身份 | 单词、文章、任务的稳定 ID 是什么？删除重建是否会绕过去重？ |
| 事件身份 | 怎样避免重试、重启、换设备重复处理同一活动？ |
| 撤销契约 | 什么时候仍能撤销？何时允许把奖励变成可消费余额？ |
| 内容线索 | 可交给 AI 的主题或词条是什么？用户隐私如何最小化？ |
| 日界线 | 哪个时区定义一天？更换时区如何避免重复结算？ |
| 货币与价格 | 显示名、奖励规则、每日上限、价格目录及规则版本是什么？ |
| 人物与素材 | 角色身份、已有动作、可用道具、许可范围是什么？ |
| 接续范围 | 只迁移室友，还是整份宿主数据？两台设备能否并行写入？ |

宿主只提供业务事实，室友不反向控制任务完成、复习评分或学习排期。最小输入协议建议为：

```text
ActivityFact = {
  eventId, hostId, subjectId, kind,
  occurredAt, dayKey, contentTags,
  status: provisional | final | retracted
}
```

`subjectId` 用于每日单位去重，`eventId` 用于事件幂等，两者不能混用。只有 `final` 事实进入可消费奖励。旧事件状态变更不是新奖励事件。

最小能力接口：读取已确认活动、请求文本生成、读取可用素材、提交存档事务、获取可注入时间。不要为了这些接口引入消息中间件；宿主内直接调用或可靠增量扫描即可。

## 4. 事实、记忆与人物变化

建议分为下列记录；这是逻辑职责，不要求一项一定对应一张表：

| 记录 | 核心内容与约束 |
|---|---|
| RoommateProfile | 稳定 ID、用户设定的底色、称呼；用户主动编辑之外不可自动整份覆盖 |
| LifeEvent | 已提交的事件、时间、参与人、地点、主题、来源活动 ID |
| Episode / Choice | 当前阶段、选项、用户选择、已读情况；未选择的分支不是记忆 |
| Relationship | 稳定人物 ID、关系事实和出处；不能只凭相似名字合并人物 |
| HabitEvidence / Habit | 候选习惯 ID、支持事件、日期、状态、屏蔽情况 |
| OpenLoop | 尚未结束的承诺、小计划、借物与约定；不能凭摘要被悄悄丢弃 |
| MemorySummary | 可重建的概括，必须指回事实；摘要不是比原始记录更高的真相 |
| Asset / Inventory / Work | 已有素材、拥有物品、已生成的实际作品和来源 |
| Wallet / PacingState | 收支流水、节奏结果、规则版本；模型没有写权限 |

生成时优先带上固定底色、当前未完事项、相关人和物、近期经历、少量相关往事，而不是无限拼接全历史。初版按 ID、主题标签、日期检索即可，不默认部署向量数据库。

人物更新流程：已提交事件 → 提取候选记忆 → 检查来源与冲突 → 应用允许的增量变化 → 保存版本。一次回答或一次失败不能直接永久改变性格。暂不开放模型对核心性格维度的自由数值修改；通过兴趣、习惯、语言风格和关系表达成长。

用户可纠正事实、屏蔽不喜欢的习惯。被纠正的内容保留修订关系，后续摘要不得把旧错误复活。普通遗忘可减少无关细节进入提示词，不自动删除承诺、收藏、余额或用户标记的重要回忆。

## 5. 自主习得频率：可执行契约

### 5.1 适用范围与证据

本函数只控制“自然形成的新习惯”，不锁普通动作、已有习惯、免费交流；用户明确教口头禅或购买一个已展示的动作，是主动操作，另走相应确认流程，不伪装成随机习得。

候选必须使用规范化 `habitId`；“雨天喝茶”换一种文字不能成为第二个新习惯。支持来源可以是宿主活动引发的实际尝试，也可以是已经提交的自主生活事件。仅仅检索到一个词、生成了一段未采纳的草稿、重读旧故事，都不算新的行为证据。

每个习惯每天最多记一次支持；保留原事件 ID。证据筛选必须发生在结算之前。晚到的候选不能再次开启当天抽取；不得让 AI 为满足门槛一天虚构三个日期。

### 5.2 初始参数与函数

以下是经过函数测试的原型参数，不是用户确认的最终平衡值，也不是论文验证的宠物成长速度：

```text
minEvidenceDays = 3
minGapDays = 4
windowDays = 14
maxNaturalHabitsPerWindow = 2
strength(n) = 1 - exp(-0.35 * n)
p(n) = min(0.30, 0.08 + 0.20 * strength(n))
```

该组系数的概率实际渐近于 0.28，0.30 是保护上限，不是实际一定达到的概率。

完整调用契约：

```text
DecideHabit(state, closedDay, verifiedEvidence, draw, policy):
  1. 如果 closedDay <= state.lastEvaluatedDay，返回旧状态，不抽取。
  2. 为当日存在合格新证据的候选增加一个支持日期，排除已形成/屏蔽项。
  3. 统计形成日满足 0 <= closedDay - formedDay < 14 的自然习惯。
  4. 已有两个，或与最近一次自然形成不足四天：保存本日“无新增”结果。
  5. 只保留今天有新证据且支持日期数 n >= 3 的候选。
  6. 候选按 n 降序、habitId 升序排序，选第一个；没有候选则保存“无新增”。
  7. draw < p(n) 时形成这一个习惯，否则无新增；两种结果都保存。
  8. 状态、证据、当日决策与新习惯在同一事务提交。
```

`draw` 范围为 [0,1)，生产中由持久角色 ID、日期和固定算法版本稳定派生或预先持久化；测试时注入。不对每个候选分别抽取，否则候选越多当天至少中一次的概率越大。

一天只结算一次已封口的生活证据批次，建议在次日首次进入时结算上一有证据日。没有证据的离线日不生成补账；长时间未打开最多展示最新一份回顾，不在一次回归里循环补发多个习惯。不要在晨间空数据时消耗今天的结算资格。

`dayKey` 采用存档中的时区，时区变更不重写旧日键；拒绝逆序结算，不根据设备改时钟重开已结算日期。离线个人应用不声称具备服务器级防篡改。

### 5.3 原型的边界

本仓库 scratch 中有 Python 验证件，但它不属于应用 source set，复制本手册到别处也不依赖该文件。执行者按以上契约用宿主语言实现纯函数。

原型只接受已筛选证据；未实现素材校验、数据库事务、日终批次、证据过期、长期习惯容量与完整同步。没有这些外围机制不能宣称功能已完成。生产验证应补测长期候选饥饿、陈旧证据和半年习惯数量，再决定是否添加窗口或排序策略，不擅自把所有参数说成科学定律。

稳定随机数只避免重抽，不解决两设备不同历史；并行写入问题见第 11 节。

## 6. 生活节奏与共同小计划

建议初版每天最多自动准备一份新的主要生活片段，可有 2–4 个短镜头；用户主动互动不是只能做一次，但受每次动作防连点和 AI 调用预算约束。以上数量先用于演示，并非最终限制。

- 最多同时推进两条开放的小计划；优先续写旧事，避免每天认识一批新朋友。
- 以主题、参与者、事件模板记录近期使用情况，不只是对文字做重复检查。
- 日常、旧事后续、意外小事混合；不要求天天发生大事，也不把每天都“形成新习惯”当新鲜感。
- 用户决定只锁定当前分支。跳过时走预先允许的温和自主分支，不自动替用户花钱、答应关系承诺或送出物品。
- 送礼记录成为后续事件线索；普通故事不能要求再次付费才能看已承诺的结局。
- 室友摆摊的作品内容先生成、校验并可预览，再上架；购买只是取得已确定的作品，不是付钱后再赌生成是否成功。
- 角色自己攒钱或买东西是独立的叙事经济，不得偷偷花玩家钱包，也不能经转卖、返礼形成无限货币循环。

## 7. 奖励、购买与撤销

通用原则：奖励取自真实已确认行为，与 AI 输出、剧情成功、用户选择的讨喜程度无关。正确率不额外加价；不因答错或缺席扣罚。宿主奖励政策不改变宿主业务规则。

词间初始建议供演示：若 N 为当天已确认的不同合格词数，奖励 `R(N)=min(N,30)+5*[N>=5]`，最多 35 小鱼干。该公式、阈值和价格尚未最终确认；其他软件必须换成自己的业务单位，不能照搬“词数”。

实施契约：

1. 撤销窗口内收益标为待确认，不得消费。超过窗口后重新核实源事实仍存在且有效，才入账；重启后可重新扫描，不依赖一个内存计时器。
2. 以角色、宿主、日期、奖励类型和业务单位的组合键去重；每日里程碑有独立唯一键。规则版本单独记录，升级版本不产生第二次领取资格。
3. 开启系统前的历史默认不追溯发放；是否送欢迎礼另定，不把历史全库扫描变成意外巨款。
4. 发放上限与里程碑基于已确认单位集合统一结算，不把每条日志的“+1”盲加。当天规则快照固定，调整从下一日开始。
5. 余额来自收支流水；发放、扣款、库存、赠送和作品所有权必须可审计、可重试且原子提交。
6. 买东西前校验库存、价格和余额；双击只扣一次，失败不扣款。模型只可推荐已有商品 ID，不可决定价格或直接修改余额。
7. 正常撤销不能留下可消费奖励；超出宿主原有撤销期限的管理性回滚需要单独政策，不任意追债、制造负余额或删掉用户购买物。
8. 删除已经完成的故事或词条不等于撤销过去真实活动。防删除重建重复领币依靠稳定业务身份，具体规范由宿主适配器定义。

价格目标建议：轻量使用当天能买一件小东西，特别礼物需两三天；用模拟账户测试购买周期，不直接采用未测的价目表。虚拟货币不涉及真实支付、广告兑换或现金兑现。

## 8. AI 的权限与生成协议

AI 是内容创作者，不是规则引擎。确定性程序管理奖励、购买、日界线、习得门槛、素材权限、候选 ID 和提交事务。

建议响应包含：`schemaVersion`、`requestId`、`baseRevision`、镜头列表、可用选项、候选事实变化、候选习惯证据、作品草稿。事实变化只允许白名单类型；不得接收任意 SQL、代码、路径、模型声明的余额或反向业务操作。

生成流水线：

1. 程序选定可生成的事件类型、参与者、可用素材、允许的变化与请求 ID。
2. 最小化提供固定底色、相关记忆、允许的活动线索；不上传密钥、整库、无关文本或原始截图。
3. 调用宿主已有文本 API；JSON 模式不等于验证通过。
4. 做结构与领域校验：ID 存在、素材匹配、选项合法、时间顺序、未完事项、事实版本及禁止项。
5. 不合格可有限修复，建议最多两次；仍不合格显示简洁失败状态，继续使用已有日常内容。
6. 只有在存档版本仍匹配时，事务提交正文与允许的变化；之后才展示。过期生成结果不得覆写用户的新选择。
7. 无新增习惯的日期，生成上下文不授权“永久学会”叙述；出现此类越权声明需拒绝或修复，不能只忽略字段却照样展示矛盾文案。

严格验证不能完全消除自然语言穿帮，需人工体验评测与用户纠错入口，不宣传“永不记错”。外部词条、用户文本、模型返回都是数据，不能当作系统指令或授权执行动作。

没有 API 或网络时：已有故事、作品、资产、动作、基础陪伴继续使用，学习照常计账；新创作可以等待。不编造“已生成”状态，不因重试重复扣币，不在每次点宠物时自动调用模型。

## 9. 视觉素材与非图片创作

素材适配表至少包括 `assetId`、文件摘要、动作标签、播放策略、尺寸、背景/透明信息、可搭配道具和替代素材。持久化用 assetId，不用机器绝对路径。

现有 GIF 可以是整幅场景或特写；不能默认具备骨骼、分层、换装、移动方向。用镜头切换、文字气泡和已有 GIF 演戏，不用模型描述冒充新动画。

### 9.1 GIF 播放规则（用户已确认）

- **循环播放**（2026-10-30 用户改，取代第一版的单次停末帧）：一次有效互动或新镜头触发后，从第一帧开始持续循环，直到换成另一个动作或离开页面；不依赖 GIF 自带循环次数，API 28+ 显式 `REPEAT_INFINITE`，26–27 用无限 `ValueAnimator` 兜底。
- 同一个动作播放中再次摸头等连续点击直接忽略：不重启、不排队、不补播。此类重复输入也不触发额外 AI 调用、扣币或重复互动记录。
- 播放由明确的触发身份驱动，不能因为界面重绘、状态订阅刷新或返回前台就重启；切到真正的新镜头才允许启动该镜头的播放。
- 动画/播放回调只更新呈现状态，不再次发奖励、写学习记录或触发习惯结算。关闭页面不阻塞主软件，后台不继续无意义播放。
- 循环接缝要逐个检查透明背景和帧处置方式，避免跳帧闪白、残影或消失；任何素材问题先在演示中展示给用户选择替代，不擅自改原文件。

### 9.2 素材与创作要求

- 文件命名可辅助自动分类，但接入前人工预览，去重、测时长、控制内存，并测试减少动态效果的呈现。
- 不覆盖原素材。导入时防路径穿越、超大文件和异常解码；素材包校验体积、文件数和摘要。
- 文本作品必须有实际正文；菜单、便签、票根可用普通 UI 排版，不必调用图片生成。
- 文本描述一件不存在图片的物品是允许的，但必须明确是文本纪念物；不能承诺能穿上或摆进房间。
- 资产下载/导入方式、应用内置体积、版权与外部分发许可在阶段 0 确认，不以“AI 可写出来”为理由忽略素材成本。

## 10. 保持宿主主功能优先

默认建议：宿主首页提供低干扰入口，点击进入独立室友空间；不在阅读、专注计时或其他核心任务上盖会动的宠物。不自动新增顶级导航栏，入口位置由宿主适配确认。

普通互动可以是点击回应、短选项、道具和共同计划，不把初版变成无限自由聊天窗口。自由输入的范围、内容安全与预算是后续独立决策。

故事可稍后看、可跳过、可回看；不自动刷屏通知。货币收获合并呈现，重复打开不重复弹“新发现”。规则说明集中放帮助页，不把控制公式展示成日常负担。

## 11. 备份、迁移与设备接续

备份必须包含：角色 ID 与性格、事件/选择/关系、开放事项、习惯证据和节奏结果、钱包流水与库存、作品正文、奖励处理进度、规则版本、日界线和素材清单。密钥不进存档，目标设备自行配置。

素材可单独以内容摘要存储，只上传缺失资源，避免每天重传所有 GIF；先完成所引用对象，再发布可恢复的清单。缺素材须明示和提供重导入口，不能默默丢角色。存档大小和实际流量需测量，禁止套用无媒体旧备份的估算。

“备份恢复”“单活跃设备接续”“两台同时离线使用后合并”是三种不同交付，不能混称同步。

- 初版推荐先做安全备份恢复，再确认是否采用单活跃设备接续；这项体验取舍需用户确认。
- 每个快照有 snapshotId、parentRevision、schemaVersion、摘要和创建设备信息；日期文件名不能单独当作冲突控制。
- WebDAV 是否可靠支持条件写入、原子发布或锁需要实测，不能假定。没有可靠能力就提供明确手动交接，不包装成无冲突自动同步。
- B 设备接续前校验并保存本地安全副本；旧 A 设备不能用旧状态覆盖云端。无法证明唯一写入权时暂停共享钱包消费，而不是离线花两次再相加。
- 不能用“最后修改时间较新者覆盖”合并余额、选择和习惯。若需真正多写者，另立同步方案；禁止把 CRDT 当一句口号解决花钱冲突。
- 恢复先验证完整性、版本和引用对象，再进行可恢复的替换。中断、磁盘不足、权限异常时旧数据必须还在；全流程测试用测试存档。

固定随机种子不等于多端一致性，复制正在写的数据库不等于一致性快照，整库恢复也不等于只迁移室友。

## 12. 当前研究依据与缺口

- [Generative Agents，2023](https://arxiv.org/html/2304.03442v2)：论文描述记忆检索、累计重要性超过阈值触发反思；可支持“经历与反思分层”的设计方向，不证明本手册参数、长期人格稳定或宠物成长速度。
- [Lally 等，2010](https://onlinelibrary.wiley.com/doi/abs/10.1002/ejsp.674)：已核对检索摘要中的重复行为与渐近拟合描述；研究对象是真人，不可把天数当成虚拟室友规则。本次未取得出版站全文。
- [任天堂：与居民互动](https://www.nintendo.com/zh-hans-hk/switch/blfga/enjoy/index.html)、[建造岛屿](https://www.nintendo.com/zh-hans-hk/switch/blfga/create/index.html)、[游戏介绍](https://www.nintendo.com/zh-hans-hk/switch/blfga/index.html)：已核对官方描述的性格、居民生活、赠礼、微个性、口头禅与商店。仅借鉴体验，不复制人物、图片、文案或整套系统。
- GitHub：用户要求的源码核对尚未完成，因本机 gh 不可用且临时工具准备被权限阻断。接手者须先核对可用工具/获得必要授权，再找到对应开源实现，记录许可证、固定 commit、关键函数和与本方案的差异，不能用搜索摘要冒充读过代码。
- Valve AI Director 演讲仅定位到材料，PDF 未完整读取，不把具体状态机或时间参数作为已验证依据。

节奏原型已通过 9 项测试，包含 365 天极限候选输入的上限检查，但它们只证明规则性质，不证明用户觉得好玩。GitHub 缺口不阻止画交互演示，但在把算法称为经源码调研的正式方案前必须补齐。

## 13. 分阶段执行与验收门

每阶段先说明输入、会改哪些文件、用户会看到什么；阶段通过后才进入下一阶段。用户未要求提交时不 commit。下面是实施顺序，不是授权一次性实施所有阶段。

| 阶段 | 工作 | 必须交付的验收证据 |
|---|---|---|
| 0 现状与契约 | 读宿主规范、核对业务事件与备份、补 GitHub 调研、填第 3 节适配表 | 已确认/建议/待决清单；无覆盖用户改动；无虚假源码引用 |
| 1 可玩演示 | 用固定内容和已有素材走初识、免费互动、收礼、摆摊、一个小计划 | 用户能实际点完一天到第三天，确认性格卡、字数和交互节奏；不连接真实资产 |
| 2 确定性内核 | 实现活动归一、奖励与钱包、候选证据、习得函数、状态存储与迁移 | 去重、撤销、购买原子性、节奏边界和迁移测试；模型完全不参与记账 |
| 3 记忆与文本 AI | 加入有来源的记忆、受控增量、结构化生成、失败恢复和预算 | 同一人物与旧选择在多次故事中一致；坏 JSON/越权资产/超时不污染存档 |
| 4 生活闭环 | 真实宿主活动→次日见闻→选择/赠礼→后续→收藏与自主习惯 | 真实设备走完整链路；少量长期存档回放，不用纯生成截图代替交互验收 |
| 5 备份与接续 | 一致性快照、媒体、恢复失败保护；按确认范围做安卓或其他设备接续 | A→B 保留记忆/钱包/作品/节奏；旧A不覆盖；断网/中断/损坏文件不丢数据 |
| 6 长期体验 | 回放30/90/180天与至少一周人工体验，调参数与内容重复控制 | 习惯增长分布、购买周期、重复率、调用成本与用户反馈；列已知限制 |

真实数据迁移前先备份并验证可恢复；不得用真实账号消费、用户主数据库、云端旧快照做破坏性测试。

## 14. 必测清单与移交格式

- 重复点击、重试、重启和跨页面处理同一活动，不重复奖励。
- 正确、错误、只看、当堂重练、提前活动各按宿主契约处理；不改变主业务统计。
- 撤销窗口边界、跨午夜撤销、里程碑刚达标又撤销、到上限后继续活动不多发钱。
- 一年每天大量候选、随机数强制为零，仍满足最小间隔和任意14天最多两次；同一天失败后不能重抽。
- 没学习仍可有自主生活；没打开不无限补发；屏蔽习惯不被换名学回；无素材不宣称新动画。
- 新作品有正文后才上架；购买失败、重复赠送、过期价目、资产已售罄都不错误扣款。
- 同时两个生成请求、生成中用户选了分支、AI返回旧版本/非法ID/越权货币，均不覆写状态。
- 旧记忆与新事实冲突可纠正；拒绝把未选择的分支、用户不在场的承诺当成共同经历。
- 备份不带密钥；不同版本、媒体缺失、磁盘不足、恢复中断、两端旧存档均有明确结果。
- GIF摸头播放一次后停在末帧，等待至少两个原动画周期仍不自动重播；再次摸头才从头播放，播放中连续点击十次不重启也不在结束后补播。
- GIF自带无限循环、透明背景和局部更新帧时仍正确保留最终合成画面；重绘和前后台切换不重播已结束动作，不额外产生业务记录。
- 读屏、字体放大、减少动画、后台耗电、GIF解码内存及宿主核心页面回归通过实际设备检查。

每阶段交付只报告真实状态：完成的功能、修改文件、实际测试、未做或受阻项、启动/查看方式，以及给用户的编号体验清单。不得把“计划支持”写成“已支持”。

给下一位 AI 的首条指令：先阅读本手册与目标宿主附录，完成阶段 0 的只读核对，向用户说明第一个可体验的小阶段；不要直接全量改代码，也不要重新追问已经确认的产品方向。
